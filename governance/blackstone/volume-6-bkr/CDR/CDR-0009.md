# CDR-0009 — Relocate Registry Validator Out of governance/blackstone

## Problem

Automated review of PR #242 (`chatgpt-codex-connector[bot]`) identified that
CDR-0008 placed `validate_registry.py` at
`volume-6-bkr/REGISTRIES/validate_registry.py` — inside
`governance/blackstone/`. `governance/blackstone/AGENTS.md` Local Contracts
state explicitly: **"No code, product feature, or operational schema may be
placed in this subtree."** This is a binding local contract, distinct from
`ARCHITECTURAL_FREEZE_NOTICE.md` §3–4 (which permits the *concept* of
governance tooling operating on the existing architecture, but does not
override the subtree's own zero-code rule). CDR-0008's decision satisfied the
architectural-freeze constraint but overlooked this separate, stricter local
contract.

The same review also identified two logic gaps in the validator that should
be corrected in the same pass, since the script is being edited regardless:

1. The validator read only `constitution_registry.json`; it never parsed
   `constitution_registry.md`, so it could not detect drift between the
   authoritative Markdown table and its derived JSON mirror — the exact risk
   CDR-0008 introduced it to guard against.
2. Supersession validation checked only `superseded_by` → `supersedes`. A
   malformed entry with a `supersedes` reference but no matching reverse
   `superseded_by` on the target would pass despite the documented reciprocal
   invariant.

## Alternatives Considered

1. **Leave the script in place.** Rejected: violates a binding,
   unambiguous Local Contract in `governance/blackstone/AGENTS.md`; not a
   judgment call.
2. **Delete the validator entirely rather than relocate it.** Rejected: the
   validator has already demonstrated value (it caught real drift during
   this correction, see Verification below); removing it would discard
   working governance tooling to solve a placement problem that has a
   direct fix.
3. **Relocate the script to `scripts/governance/validate_constitution_registry.py`,
   entirely outside `governance/`, and fix the two logic gaps in the same
   commit.** Selected: satisfies the AGENTS.md constraint, follows the
   existing repository convention of standalone, non-CI-wired scripts under
   `scripts/` (e.g. `scripts/ci/validate_repository_claims.py`, which is
   itself CI-wired — this validator is deliberately kept out of
   `scripts/ci/` to avoid implying CI wiring that CDR-0008 explicitly
   deferred), and corrects the two logic gaps while the file is already
   being edited.

## Decision

- Delete `governance/blackstone/volume-6-bkr/REGISTRIES/validate_registry.py`.
- Add `scripts/governance/validate_constitution_registry.py` (outside
  `governance/` entirely), with the same checks as before plus:
  - Parses `constitution_registry.md`'s two tables and cross-checks every
    field against `constitution_registry.json`, failing on any drift.
  - Checks supersession reciprocity in both directions
    (`superseded_by` ⇄ `supersedes`).
- Still **not** wired into `.github/workflows/ci.yml` — CDR-0008's deferral
  to GBC-2 entry criteria is unaffected by this relocation.
- Update all references to the old path (`BKR.md`, both volumes'
  `CHANGELOG.md`, `constitution_registry.md` "Related Tooling",
  `CDR-0008.md` is left unmodified per CDR immutability; this CDR is the
  correction record) to point at the new location.
- Correct `CDR/INDEX.md`'s `CDR-0007` row: `Amendment Class` was recorded as
  `Editorial`, but `CDR-0007.md`'s own front matter states `Minor` (also
  flagged by the same review). This is a transcription fix to the derived
  index, not a change to CDR-0007 itself, and does not require its own CDR
  (`INDEX.md` Rule 4: "This index does not alter the status or authority of
  any CDR").

CDR-0008 remains unmodified and is **not** marked `Superseded By` this CDR:
its core decision (add index, dependency graph, JSON mirror, and a
standalone non-CI validator, entirely deferring CI wiring to GBC-2) stands.
Only the specific claim that the validator lives under
`volume-6-bkr/REGISTRIES/` and that "no file outside `governance/` is
touched" is corrected here; readers of CDR-0008 should treat those two
statements as historical (accurate as of 2026-08-01, corrected 2026-08-02 by
this CDR).

## Governing Principles

- `governance/blackstone/AGENTS.md` Local Contracts — "No code, product
  feature, or operational schema may be placed in this subtree." (binding,
  takes precedence over CDR-0008's original placement choice.)
- `ARCHITECTURAL_FREEZE_NOTICE.md` §3–4 — governance tooling concept remains
  permitted; only its file location changes.
- CDR-0006 — "CDRs are immutable; corrections require a new CDR."

## Expected Consequences

- `governance/blackstone/` contains zero executable code, satisfying its own
  AGENTS.md contract.
- The validator gains real drift detection between the Markdown registry and
  its JSON mirror, and bidirectional supersession checking — closing the two
  P2 gaps identified alongside the P1 placement violation.
- `CDR/INDEX.md`'s CDR-0007 row now matches CDR-0007.md's own declared
  amendment class.
- No change to CDR-0008's underlying decision to add lightweight tooling, to
  the deferral of CI wiring, or to any constitutional document's content or
  status.
