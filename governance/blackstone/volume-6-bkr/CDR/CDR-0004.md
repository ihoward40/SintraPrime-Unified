# CDR-0004 — Knowledge Core as Canonical Semantic Authority

## Problem

Without a single semantic authority, agents, APIs, and registries can use the same word with different meanings, leading to interoperability failures and audit ambiguity.

## Alternatives Considered

1. **Let each engine define its own vocabulary.** Rejected because it produces terminology drift.
2. **Central Knowledge Core (BKC).** Selected because it provides a single vocabulary for all implementations.

## Decision

BKC is the canonical semantic authority for all governance implementations. Every schema, ontology, registry, API, and engine MUST derive its vocabulary from BKC. Terms are recorded in BKR.

## Governing Principles

- BKC-C-001 Semantic Authority
- BKGC § 1 Definitions

## Expected Consequences

- Cross-agent and cross-implementation communication uses consistent vocabulary.
- Test cases and APIs reference the same definitions.
- Terminology changes are governed through BKC updates.

## Revisit Conditions

If BKC becomes too large or too slow to evolve, consider domain-specific extensions rather than abandoning semantic centralization.
