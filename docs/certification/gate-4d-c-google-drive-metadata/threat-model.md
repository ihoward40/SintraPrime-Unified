# Gate 4D-C threat model

## Assets

- Principal-approved Google account binding.
- OAuth access and refresh tokens.
- Drive metadata returned under the proposed scope.
- Canonical external-action approval, execution, and evidence records.
- The frozen Gate 4D-B certified boundary.

## Trust boundaries

1. Principal → authorization record.
2. Authorization record → durable governed service identity.
3. Canonical `restricted_external_action.py` authority → protocol adapter.
4. Adapter → pinned Google Drive API destination.
5. Provider response → metadata field filter → sealed evidence.
6. OAuth token store → short-lived credential lease; raw tokens never enter intents, logs, evidence, prompts, or model context.

## Threats and required controls

| Threat | Mandatory control | Failure behavior |
|---|---|---|
| Scope escalation | Exact `drive.metadata.readonly` comparison; reject extra/missing scopes | Block before token use |
| Wrong Google account | Principal-approved immutable account digest; verify token subject/account binding | Block and revoke lease |
| Silent account switching | No ambient browser/account selection; explicit account digest required per approval | Block |
| Token leakage | Secret vault/lease only; structured redaction and entropy/pattern scans | Destroy evidence candidate; alert |
| Content exfiltration | Exact operations, GET-only, fields allowlist, deny `alt=media`, export and Docs/Sheets/Slides APIs | Block before network |
| Write escalation | Deny non-GET and every mutating method/operation | Block before network |
| Host/path confusion | HTTPS, exact host/path, DNS/IP validation, TLS verification, redirects denied | Block |
| Query injection | Parse query structurally; exact key allowlist; deny dangerous keys and duplicate ambiguity | Block |
| Over-broad metadata | Explicit `fields` mask generated by authority; reject unknown response fields | Mark invalid; do not expose |
| Replay/duplicate execution | Durable idempotency key, in-flight suppression, terminal replay | Return prior result only |
| Timeout ambiguity | Provider-attempt lifecycle and reconciliation; no blind retry | INCOMPLETE pending reconciliation |
| Rate abuse | Per-account, per-operation, and global durable buckets | Throttle/block |
| Kill-switch bypass | Global, adapter, account, and operation switches checked immediately before I/O | Block |
| Evidence tampering | Append-only hash chain, external record hash, secret scan before sealing | Reject certification |
| Authority inheritance from 4D-B | Separate gate IDs, adapter IDs, approvals, workflows, and freeze record | Block |

## Non-goals

This design does not authorize implementation, OAuth consent, account connection, metadata retrieval, contents access, or side effects. It does not certify Google identity correctness or provider behavior; those require a later authorized ladder.
