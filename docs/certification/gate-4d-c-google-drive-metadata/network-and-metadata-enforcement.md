# Network and metadata-only enforcement

## Exact API surface

Proposed operations:

- `GET https://www.googleapis.com/drive/v3/files`
- `GET https://www.googleapis.com/drive/v3/files/{fileId}`

No other Google host, API, method, or path is in scope. In particular, Docs, Sheets, Slides, People, Admin, OAuth token, upload, export, and permission endpoints are not connector destinations. OAuth endpoints, if later authorized for connection, belong to a separate account-connection component and authority record.

## Destination enforcement

Before I/O and after DNS resolution:

- scheme must equal `https`;
- host must equal `www.googleapis.com` after IDNA/canonical parsing;
- port must be 443 or absent;
- path must match one of the two exact templates;
- userinfo and fragments are rejected;
- redirects are disabled and every 3xx is terminal;
- proxy environment variables and alternate transports are disabled;
- resolved addresses are validated against the approved Google endpoint policy and pinned for the request lifetime;
- TLS verification and hostname validation are mandatory.

## Request restrictions

- Method is exactly `GET`.
- `alt`, `uploadType`, `upload_protocol`, and `acknowledgeAbuse` are always rejected.
- `fields` is generated by the adapter from the authority contract; callers cannot supply arbitrary field masks.
- `q` is parsed/escaped as data and cannot alter method, host, path, or fields.
- File IDs are opaque path segments and must pass strict length/character validation.
- Pagination tokens are opaque response-derived values bound to the same intent/account/query digest.
- Maximum page size, total pages, response bytes, and wall time are bounded.

## Response restrictions

The adapter parses JSON and projects only expressly allowed metadata fields. Unknown or content-bearing fields cause fail-closed invalidation; they are never forwarded to a model or evidence narrative.

`webContentLink`, `webViewLink`, `thumbnailLink`, `iconLink`, `exportLinks`, `contentHints`, `indexableText`, `description`, `appProperties`, `properties`, permission details, owners' email addresses, and arbitrary extension data are excluded unless separately reviewed and added to a later contract.

No response body is persisted outside sealed evidence. Evidence stores a redacted metadata-field inventory, item count, status, and response hash—not tokens or content.

## Canonical authority integration

A future adapter may validate, translate, and perform provider I/O, but it may not mint approval, choose credentials/accounts, widen scope, own durable replay state, bypass rate limits/kill switches, or synthesize evidence. Those stay in `portal.services.restricted_external_action` and its durable records.
